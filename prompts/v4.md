# jobq — v4 (multi-phase, high give-away)

This build is delivered as **phases**, pasted one at a time. Do **only** the current
phase, make its **verification** pass, then stop and wait for the next. Each phase hands
you the shape of its piece (types, signatures, which step is atomic) and the questions
whose answers are the hard lines; the bodies are yours. Keep earlier phases working.
One directory, one wolf module, one `main`.

---

### PHASE 0 — Setup & spec

First run `cp ../../README.md ./README.md && cp ../../../WOLF-NOTES.md ./WOLF-NOTES.md`,
then read both fully, then `std/fs/fs.lu` (`create_new`, `move_file`, `entries`,
`read_dir`) and `std/process/process.lu`'s header. Create `main.lu` with a
`usage() -> str` (the two lines of README §4) and a `main` that prints the usage and
returns 2 with no arguments, 0 for `--help`, and `jobq: unknown subcommand X` with 2
otherwise.

**Verify:** `wolf build main.lu -o jobq` warning-free; `./jobq --help; echo $?` → `0`;
`wolf fmt --check *.lu`.

### PHASE 1 — The store (M1)

Create `store.lu`:

```wolf
use std.fs
use std.str
use std.time

/// A job's record; the file is `key=value` lines, `cmd` as a JSON array of strings.
pub struct Job {
    id: int,
    cmd: List[str],
    added: int,
    tries: int,
    runner: str,
    lease: int,
    status: str,    // "", "ok", "failed", "killed", "lease-expired"
    started: int,
    ended: int,
    exit: int,      // -1 when absent
}

error store_errors = {not_found, denied, exists, io, malformed}

pub fn file_name(id: int) -> str                      // six-digit sequence, then the id
pub fn write_text(j: Job) -> str
pub fn parse_text(text: str) -> Job ! {malformed}     // missing/repeated key, bad number
pub fn read_job(path: str) -> Job ! store_errors
pub fn write_job(path: str, j: Job) -> () ! store_errors
fn highest_id(dir: str) -> int ! store_errors         // across the four state dirs
pub fn init(dir: str) -> () ! store_errors
pub fn add(dir: str, cmd: List[str]) -> int ! store_errors
```

`add` allocates `highest_id + 1` and creates the record in queue/ with the one
`std.fs` call that fails on an existing file instead of truncating it; on its
`exists` row the next id is tried. Why is "list, then create" racy without that call,
and why is the retry loop still needed with it? Create `argv.lu` (`split_line`,
`json_argv`, `parse_argv`; your own JSON strings, no `std.json`). Wire `init`, `add`,
`add -f`, `ls`, `show`. Tests for the quoting rule and the round trip.

**Verify:** A1, A2.

### PHASE 2 — A serial runner (M2)

Create `runner.lu`:

```wolf
use std.process

/// Claims `name` for `runner`: the rename queue/ → running/ is the atomic step (a
/// loser sees not_found); the winner then rewrites the record with runner and lease.
pub fn claim(dir: str, name: str, runner: str, lease_ms: int) -> Job ! store_errors

fn claim_round(dir: str, runner: str, lease_ms: int, want: int) -> List[Job]
fn start_job(dir: str, j: Job) -> process.Child ! {unsupported, invalid, not_found, denied, io}
pub fn finish(dir: str, j: Job, status: str, exit: int) -> () ! store_errors
pub fn run_jobs(dir: str, jobs: int, lease_ms: int, max_tries: int, follow: bool) -> int
```

(`claim` and `finish` may live in `store.lu` instead.) `fs.move_file` is the rename;
read its doc on this pin, and use the `fs_rename` builtin if it copies. `run -j 1`:
one claim round, `start_job` with stdout and stderr to the log file through
`set_stdout`/`set_stderr`, `wait_status`, `finish`. Exit 1 when any job failed.

**Verify:** R0, F1's first half.

### PHASE 3 — `-j N`, leases, retry, stats (M3)

Up to N children at once (`process.poll()` if the pin has it, else wait on the oldest
slot; say which in a comment); `renew` every lease/3; `retry`; `stats`. In-process
test: two claimers over a temp dir, 50 jobs, each claimed once.

**Verify:** R0 with `-j 4`, S1, F1 whole, `wolf test .` green.

--- END PHASE 3 ---

### PHASE 4 — Racing runners and lease expiry (M4)

`reclaim_expired` (tries + 1, `lease-expired` at `--max-tries`, the attempt's log kept
as `log/<id>.<tries>.log`); the malformed-file skip. Work out the worst-case time
between a runner's `kill -9` and another runner starting its job, and make R2/R3's
`--lease 2` fit it. Write `test.sh`: build (a build failure is a failure), then R1 three
times: a fresh queue and an empty `out/`, 500 jobs of `sh -c 'printf x >> out/$1' _ ID`,
four `jobq run -j 4 &` on the one directory, `wait` on all four, then assert 500 files
in `out/` and none with a size other than 1, printing `ok R1 rep<N>` or the counts on
failure. Then the other rows, and a non-zero exit on any failure.

**Verify:** R1 three times, R2, R3, M1.

--- END PHASE 4 ---
